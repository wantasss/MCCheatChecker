Анализ процесса javaw
Перед поиском каждого шаблона мы находим нужный процесс, нажимаем по нему ПКМ, выбираем Properties, далее переходим в пункт Memory → Options → Strings → Выставляем все галочки, ставим цифру 4 вместо 10 и осуществляем поиск.
Найдите конкретный javaw.exe процесс, принадлежащий экземпляру Minecraft.
Найдите строки, содержащие общие имена подкаталогов, например \mods или \versions.\resourcepacks
Проверьте полученные полные пути, найденные в памяти процесса. Эти пути покажут точные каталоги, к которым активно обращается запущенная игра, подтвердив правильное .minecraft расположение и подпапки, например mods.
Структура и соответствующие подкаталоги: В правильной корневой папке игры есть несколько подкаталогов, которые особенно важны для обнаружения читов:
versions/: Содержит подпапки для каждой установленной версии Minecraft (ванильной или модифицированной, например, Forge/Fabric). Внутри них находятся основные .jar файлы игры (которые могут быть целями для Javaedit) и связанные с ними библиотеки.
mods/: Здесь .jar размещаются файлы модов Forge или Fabric, которые загружаются игрой. Эта папка — основной объект анализа.
libraries/: Хранит необходимые библиотеки Java, необходимые для Minecraft и Forge/Fabric. Иногда здесь могут размещаться изменённые или вредоносные библиотеки.
logs/: Содержит файлы журналов, созданные игрой и Forge/Fabric (например, latest.log, debug.log). В них могут отображаться ошибки, загруженные моды, а иногда и информация о ходе игры, полезная для контекста.
config/: Часто содержит файлы конфигурации ( .cfg, .toml, .json) для установленных модов, которые могут выявить подозрительные настройки.
resourcepacks/& shaderpacks/: Хотя здесь обычно содержатся косметические активы, проверка дат изменений или необычных типов файлов иногда может быть полезна.Использование различных строк для поиска улик

Анализ процесса explorer.exe
Перед поиском каждого шаблона мы находим нужный процесс, нажимаем по нему ПКМ, выбираем Properties, далее переходим в пункт Memory → Options → Strings → Выставляем все галочки, ставим цифру 4 вместо 10 и осуществляем поиск.
Распространенные шаблоны поиска:
pcaclient (Filter – Contains – Case insensitive): Поиск кэшированных строк, связанных со службой «Помощник по совместимости программ». Иногда это может выявить пути к недавно запущенным программам (обычно последние ~10), хотя это легко обойти. Скопируйте полные блоки результатов, содержащие эту строку, в Блокнот для упрощения анализа.
file:/// (): Список путей к файлам (часто в формате URI), к которым недавно осуществлялся доступ или которые просматривались через Проводник или связанные операции оболочки. Может предоставлять контекст, но обычно содержит информацию о легитимной активности и не подтверждает выполнение. Дальнейшая фильтрация (например, по .exe, .dll, .jar, определённым каталогам пользователя) в этих результатах может дать полезные результаты.

Анализ процесса csrss
Перед поиском каждого шаблона мы находим нужный процесс, нажимаем по нему ПКМ, выбираем Properties, далее переходим в пункт Memory → Options → Strings → Выставляем все галочки, ставим цифру 4 вместо 10 и осуществляем поиск.
Распространенные шаблоны поиска (регулярные выражения, без учета регистра):
^[A-Z]:\\.+.exe$: Находит полные пути, заканчивающиеся на .exe. В основном используется для экземпляров с меньшим количеством приватных байтов.
^[A-Z]:\\.+.dll$: находит полные пути, заканчивающиеся именно на .dll. Используется в основном на экземпляре с большим количеством приватных байтов. Крайне важно для обнаружения стандартных внедрений DLL. Обратите особое внимание на неподписанные DLL, найденные с помощью этого шаблона.
^(?:\\\\\?\\)?[A-Za-z]:\\.+$: более широкий шаблон для поиска полных путей с любым расширением или без него . Полезно для экземпляра с большим количеством приватных байтов при поиске исполняемых файлов, замаскированных под поддельные расширения (например, .tmp, .png), или файлов без расширений, запущенных с помощью определенных методов. Также может помочь в поиске DLL-библиотек.
СЛУЖБА CSRSS ЧАСТО МОЖЕТ БЫТЬ ЗАБЛОКИРОВАНА КОМПЬЮТЕРОМ ПО МНОЖЕСТВУ ПРИЧИН! Зачастую она может быть защищена функцией KernelDrive (не включать, у игрока может вылезти синий экран)Также любые манипуляции с ней могут быть ограничены античитами игр ( Vanguard, Faceit и другие ) в связи с тем, что игрок может использовать Kernel-читы в их играх.Если у вас не получается с ней работать и доступ к ней ограничен - в целях безопасности игрока оставьте ее и перейдите на альтернативный метод.
